# 📖 3.04. Merge
**Merge** é o processo utilizado pelo Git para integrar alterações de uma branch em outra.

Por exemplo, depois de desenvolver uma alteração na branch `feature/login`, podemos integrá-la à branch `main`.

```text
main
  │
  └── feature/login
          │
          ├── alteração
          └── commit
```

Depois do merge:

```text
main
  │
  ├── alterações anteriores
  └── alterações da feature/login
```

O comando `git merge` combina o histórico da branch indicada com a branch atual. 

## Como fazer um Merge?
Imagine que um projeto de automação possui a branch `main` e você precisa adicionar testes para a funcionalidade de login.

Você poderia:

Criar a branch
```
git branch test/login
```

Fazer as alterações e criar um commit:

```
git add .
git commit -m "Add login tests"
```

Depois, voltar para a `main`:

```
git switch main
```

E integrar as alterações:

```
git merge test/login
```

Assim, o merge integra alterações/históricos realizados na branch `test/login` à `main`.

## Fast-Forward Merge
Em algumas situações, o Git pode realizar um **fast-forward merge**.

Isso acontece quando a branch atual não possui novos commits desde que a outra branch foi criada. Nesse caso, o Git pode simplesmente avançar a referência da branch atual para o commit mais recente da outra branch, sem criar um novo merge commit. 

Exemplo:

```
Antes:

main
 │
 A──B
     \
      C──D  feature/login


Depois do merge:

A──B──C──D  main
```

## Merge Conflict
Um **merge conflict** acontece quando o Git não consegue combinar automaticamente alterações feitas nas branches.

Isso pode acontecer, por exemplo, quando diferentes branches modificam a mesma parte de um arquivo de maneiras conflitantes.

Quando isso ocorre, o Git interrompe o merge e indica os arquivos que precisam ser analisados. 

O arquivo pode apresentar marcadores indicando as alterações conflitantes:

```
<<<<<<< HEAD
Alteração da main
=======
Alteração da feature
>>>>>>> feature/login
```

É necessário analisar o conflito, escolher ou combinar as alterações desejadas e remover os marcadores.

Depois disso, o arquivo deve ser adicionado novamente à Staging Area e o merge pode ser concluído:

```
git add <nome do arquivo>
git commit
```

O `git status` também pode ser utilizado para identificar arquivos que estão em estado de conflito.

## Cancelando um Merge
Se um merge resultar em conflitos e for necessário desistir da operação, o Git disponibiliza:

```
git merge --abort
```

Esse comando tenta retornar o repositório ao estado anterior ao início do merge. 

## 💡 Merge no dia a dia de QA
Branches permitem que alterações relacionadas aos testes sejam desenvolvidas separadamente da branch principal.

Por exemplo:

```text
main
 │
 └── test/login
        │
        ├── adicionar teste
        ├── executar teste
        └── commit
```

Depois que o trabalho estiver concluído, o merge pode integrar essas alterações à branch principal.

No trabalho em equipe, essa integração também pode acontecer por meio de um **Pull Request**, que será estudado no próximo tópico.
