# 📖 3.05. Pull Requests
Um **Pull Request (PR)** é uma solicitação para integrar as alterações de uma branch em outra branch do repositório.

No GitHub, o Pull Request permite apresentar as alterações realizadas, explicar o que foi desenvolvido e, principalmente, revisar o código antes da integração. Durante esse processo, outras pessoas da equipe podem analisar as mudanças, fazer comentários, sugerir melhorias e discutir possíveis ajustes.

Após a revisão e aprovação, as alterações podem ser integradas à branch de destino por meio do merge.

Dessa forma, o Pull Request ajuda a tornar a integração das alterações mais organizada, colaborativa e segura.

## Como funciona?

Considerando um projeto de testes automatizados, um fluxo simples pode ser:

```text
main
  │
  └── test/login
        │
        ├── adicionar testes de login
        ├── executar os testes
        └── commits
                │
                ▼
          Pull Request
                │
                ├── Review
                ├── Feedback
                └── Aprovação
                │
                ▼
              Merge
                │
                ▼
              main
```

Depois de concluir o trabalho, a branch pode ser enviada para o GitHub e um **Pull Request** pode ser aberto para solicitar a integração das alterações na `main`.

Nesse caso, a `test/login` é a **branch de origem**, que contém as alterações, enquanto a `main` é a **branch de destino**, que receberá essas alterações.

Durante o Pull Request, a equipe pode revisar os arquivos modificados, fazer comentários, sugerir melhorias e solicitar ajustes antes da integração.

Após a revisão e, quando aplicável, a aprovação, as alterações podem ser integradas à branch de destino por meio do **merge**. O processo pode variar de acordo com as regras e configurações definidas para o repositório.


## Revisão de Pull Requests
A revisão permite analisar os commits, arquivos alterados e diferenças entre as branches.

Durante uma revisão, é possível:

- comentar alterações;
- fazer perguntas;
- sugerir mudanças;
- aprovar o Pull Request;
- solicitar alterações antes da aprovação.

O GitHub disponibiliza três tipos principais de resultado para uma revisão:

- **Comment** — adiciona um comentário sem aprovar ou solicitar alterações;
- **Approve** — indica que as alterações podem ser integradas;
- **Request changes** — indica que existem alterações que devem ser realizadas antes do merge. 

## Feedback e alterações
Quando um revisor solicita alterações, o responsável pelo Pull Request pode fazer as modificações na branch de origem e enviar novos commits.

Esses novos commits passam a fazer parte do Pull Request, permitindo que a revisão continue até que os pontos levantados sejam resolvidos. 

## Pull Request e qualidade
O Pull Request também contribui para a qualidade do projeto porque permite que as alterações sejam analisadas antes de serem integradas.

Durante uma revisão, podem ser identificados problemas, dúvidas ou melhorias que precisam ser tratados antes do merge. O processo também facilita a troca de conhecimento entre os integrantes da equipe.

Para QA, esse processo pode ser utilizado para revisar alterações relacionadas aos testes, como scripts de automação, documentação ou arquivos de configuração.

## Pull Request vs Merge
Apesar de estarem relacionados, **Pull Request e Merge não são a mesma coisa**.

| Pull Request                                                  | Merge                                                  |
| ------------------------------------------------------------- | ------------------------------------------------------ |
| Propõe a integração de alterações.                            | Integra as alterações entre branches.                  |
| Permite revisão e discussão.                                  | É uma operação de integração do Git.                   |
| É utilizado como recurso de colaboração no GitHub.            | É um recurso do Git.                                   |
| Pode ter comentários, aprovação e solicitações de alterações. | Pode resultar na integração do histórico das branches. |

O Pull Request pode resultar em um merge depois que as alterações forem revisadas e os requisitos do repositório forem atendidos. 

## 💡 Pull Requests no dia a dia de QA
Um QA pode participar de Pull Requests tanto como autor quanto como revisor.

Como autor, pode abrir um PR para adicionar ou alterar testes automatizados.

Como revisor, pode analisar alterações relacionadas aos testes e verificar se elas estão de acordo com o objetivo proposto.

Esse processo ajuda a incorporar a qualidade ao fluxo de desenvolvimento, em vez de deixar a validação apenas para o final.
