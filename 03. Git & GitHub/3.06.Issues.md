# 📖 3.06. Issues
**GitHub Issues** são utilizadas para planejar, discutir e acompanhar diferentes tipos de trabalho dentro de um repositório.

Elas podem ser utilizadas para registrar **bugs, tarefas, melhorias, ideias ou outras atividades** relacionadas ao projeto. 

Para um profissional de QA, as Issues podem ser utilizadas, por exemplo, para acompanhar um defeito identificado durante os testes ou registrar uma tarefa relacionada à automação.

## Criando uma Issue
Uma Issue normalmente possui um título e uma descrição que explicam o que precisa ser acompanhado.

Uma Issue pode ser utilizada para registrar informações como:

- o problema ou tarefa;
- contexto;
- informações relevantes;
- etapas ou atividades relacionadas;
- resultado esperado, quando aplicável.

O GitHub permite criar Issues diretamente a partir do repositório.

## Organização das Issues
As Issues podem receber informações adicionais para facilitar sua organização e acompanhamento.

Alguns recursos disponíveis incluem:

- **Labels** — ajudam a categorizar as Issues;
- **Assignees** — indicam quem está trabalhando na Issue;
- **Milestones** — permitem agrupar Issues relacionadas a um objetivo ou etapa do projeto.

O GitHub também disponibiliza outros recursos de organização, mas esses são alguns dos elementos básicos utilizados para acompanhar o trabalho. 

## Issues para QA
No contexto de QA, uma Issue pode ser utilizada para acompanhar diferentes atividades.

Por exemplo:

```
Issue #15
Título: Login accepts invalid password

Descrição:
The login form allows access with an invalid password.

Expected:
The user should not be authenticated.

Actual:
The user is redirected to the application.
```

Nesse caso, a Issue registra o problema e permite acompanhar seu tratamento.

É importante diferenciar isso do **Bug Report**, estudado no Módulo 02. O Bug Report descreve o defeito de forma estruturada; a Issue é o recurso utilizado no GitHub para registrar e acompanhar esse trabalho dentro do repositório.

## Issue e Pull Request
Uma Issue pode ser relacionada a um Pull Request que implementa uma correção ou alteração.

Por exemplo:

```
Issue #15
     │
     │ correção
     ▼
Pull Request #18
     │
     │ merge
     ▼
main
```

Quando um Pull Request é vinculado a uma Issue utilizando determinadas palavras-chave, como `Closes #15` ou `Fixes #15`, o GitHub pode fechar automaticamente a Issue quando o Pull Request for integrado à branch padrão.

Esse relacionamento permite acompanhar a ligação entre o problema registrado e a alteração realizada para tratá-lo.

## 💡 Issues no dia a dia de QA
As Issues podem ajudar o QA a acompanhar problemas e atividades relacionadas à qualidade durante o desenvolvimento.

Alguns exemplos são:

- registrar um defeito encontrado durante os testes;
- acompanhar uma correção;
- registrar uma tarefa de automação;
- acompanhar uma melhoria nos testes;
- discutir uma necessidade relacionada à qualidade.

Dessa forma, as Issues ajudam a manter o trabalho registrado e facilitam o acompanhamento das atividades relacionadas ao projeto.

## Exemplo de fluxo
Um fluxo simples para QA pode ser:

```
Defeito identificado
        ↓
Issue criada
        ↓
Issue analisada e atribuída
        ↓
Correção desenvolvida
        ↓
Pull Request criado
        ↓
Issue vinculada ao PR
        ↓
Review
        ↓
Merge
        ↓
Issue encerrada
```

Esse fluxo conecta o registro do problema ao desenvolvimento e à integração da correção.
