# 3.02. Remote Repositories
Um **Repositório Remoto** é um repositório Git armazenado em um local remoto, como o GitHub, que pode ser acessado por diferentes pessoas e computadores.

Enquanto o repositório local fica no computador, o repositório remoto permite compartilhar alterações e manter uma cópia do projeto disponível para colaboração com outras pessoas ou membros da equipe.

Um projeto pode ter um repositório local conectado a um ou mais repositórios remotos.

## Local Repository vs Remote Repository
A principal diferença está no local onde o repositório é armazenado:

| Local Repository                                     | Remote Repository                                                  |
| ---------------------------------------------------- | ------------------------------------------------------------------ |
| Fica no computador.                                  | Fica em um servidor ou plataforma como GitHub.                     |
| Permite trabalhar e registrar alterações localmente. | Permite compartilhar e sincronizar alterações.                     |
| Pode funcionar sem conexão com a internet.           | Precisa de acesso ao local remoto para operações de sincronização. |

O trabalho normalmente acontece no repositório local, enquanto o repositório remoto é utilizado para compartilhar e obter alterações.

## Conectando um repositório local ao GitHub
Um repositório local pode ser conectado a um repositório remoto utilizando o comando:

```
git remote add origin <REMOTE_URL>
```

O nome `origin` é normalmente utilizado como nome do repositório remoto principal.

Depois de adicionar o remote, podemos verificar a conexão com:

```
git remote -v
```

Esse comando mostra as URLs configuradas para buscar (`fetch`) e enviar (`push`) alterações. 

## `git clone`
O comando `git clone` é utilizado para criar uma cópia local de um repositório remoto.

```
git clone <REMOTE_URL>
```

Ao clonar um repositório, o Git baixa os arquivos, commits e outras informações do repositório remoto para o computador e configura o remote `origin`.

Exemplo:

```
git clone https://github.com/LuizaTaynara/QA_Engineering_Roadmap.git
```

O `git clone` é útil quando o projeto já existe no GitHub e queremos trabalhar com ele localmente.

## `git push`
O comando `git push` envia commits do repositório local para um repositório remoto.

```
git push origin main
```

Nesse exemplo:

- `origin` identifica o repositório remoto.
- `main` identifica a branch que receberá os commits.

O `git push` permite publicar no repositório remoto os commits que foram realizados localmente. 

## `git fetch`
O comando `git fetch` busca informações e alterações do repositório remoto sem integrar essas alterações automaticamente à branch local atual.

```
git fetch origin
```

Ele atualiza as referências locais relacionadas ao repositório remoto, permitindo analisar as alterações antes de integrá-las ao trabalho local.

## `git pull`
O comando `git pull` é utilizado para obter alterações do repositório remoto e integrá-las à branch local.

Exemplo:

```
git pull origin main
```

Antes de utilizar `git pull`, é importante entender quais alterações estão no repositório remoto e como elas serão integradas ao trabalho local.

## `fetch` vs `pull`
A principal diferença é o que acontece depois que as alterações são buscadas:

- **`git fetch`** → busca as alterações, mas não as integra automaticamente à branch atual.
- **`git pull`** → busca as alterações e tenta integrá-las à branch atual.

Essa diferença é importante porque permite escolher quando queremos apenas consultar as atualizações remotas e quando queremos incorporá-las ao trabalho local. 

## Fluxo básico
Um fluxo simples entre o repositório local e o remoto pode ser representado assim:

```
Local Repository
      │
      │ git push
      ▼
Remote Repository
      │
      │ git fetch / git pull
      ▼
Local Repository
```

De forma prática, podemos:

- Fazer alterações localmente.
- Criar um commit.
- Enviar o commit para o GitHub utilizando `git push`.
- Buscar alterações do GitHub utilizando `git fetch` ou `git pull`.

## 💡 Git no dia a dia de QA
Para um profissional de QA, o repositório remoto pode ser utilizado para armazenar, versionar, organizar e compartilhar arquivos relacionados às atividades de teste, como scripts de automação, casos de teste, checklists, documentação e outros artefatos do projeto.

Por meio de um repositório remoto, como o GitHub, a equipe pode colaborar no mesmo projeto, acompanhar os históricos de alterações, revisar mudanças e fazer atualizações de forma organizada por diferentes membros do time.

No dia a dia, isso facilita a colaboração entre QA e desenvolvimento, aumenta a rastreabilidade das alterações e ajuda a manter os artefatos de teste organizados e sincronizados com o projeto.
