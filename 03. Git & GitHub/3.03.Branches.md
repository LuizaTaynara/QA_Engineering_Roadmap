# 📖 3.03. Branches
Uma **branch** é uma linha de desenvolvimento que permite trabalhar em alterações de forma isolada, sem modificar diretamente a branch principal do projeto.

Ela pode ser utilizada para desenvolver uma nova funcionalidade, corrigir um problema ou testar uma alteração antes de integrá-la ao projeto principal.

Ao criar uma nova branch, ela parte de uma branch existente e permite desenvolver alterações de forma independente. 

## Branch Principal
A branch principal é normalmente utilizada como referência principal do projeto.

No GitHub, novos repositórios utilizam `main` como nome padrão para a branch principal. Essa configuração pode ser alterada de acordo com o projeto. 

Exemplo:

```
main
 │
 ├── alteração 1
 ├── alteração 2
 └── alteração 3
```

A partir dela, podemos criar uma nova branch para trabalhar em uma alteração específica.

---

## Feature Branch
Uma **feature branch** é uma branch criada para desenvolver uma funcionalidade ou alteração específica de forma isolada.

Por exemplo:

```
main
 │
 └── feature/login
```

Nesse caso, as alterações relacionadas ao login são desenvolvidas na branch `feature/login`, sem modificar diretamente a `main`.

Branches também podem ser utilizadas para correções de bugs ou outros tipos de alterações.

## Criando uma Branch
Uma nova branch pode ser criada utilizando:

```
git branch <nome da branch>
```

Para visualizar as branches existentes:

```
git branch
```

Para trocar para uma branch existente:

```
git switch <nome da branch>
```

Também é possível criar uma nova branch e mudar para ela utilizando um único comando:

```bash
git switch -c <nome da branch>
```

O comando `git branch` pode ser utilizado para listar, criar ou excluir branches, enquanto `git switch` permite mudar para outra branch. 

## Trabalhando com Branches
Um fluxo simples pode ser:

```
main
  │
  └── feature/login
          │
          ├── alteração
          ├── commit
          └── commit
```

As alterações realizadas na `feature/login` ficam separadas da `main` enquanto o trabalho está sendo desenvolvido.

Depois que a alteração estiver pronta, ela poderá ser integrada à branch principal. 
> A integração será abordada no próximo tópico, **3.04.Merge**.

## Excluindo uma Branch
Quando uma branch não é mais necessária, ela pode ser excluída.

Para excluir uma branch local:

```
git branch -d <nome da branch>
```

O Git não permite a exclusão com `-d` quando existem alterações não integradas que podem ser perdidas. Existe também a opção `-D`, que força a exclusão da branch.

No GitHub, branches que já foram utilizadas em Pull Requests também podem ser excluídas após o trabalho ser concluído. 

## 💡 Branches no dia a dia de QA
Branches também podem ser utilizadas para organizar alterações relacionadas ao trabalho de QA.

Por exemplo, um QA pode criar uma branch para:

- adicionar testes automatizados;
- corrigir um teste existente;
- atualizar uma documentação;
- trabalhar em uma alteração específica do projeto.

Dessa forma, o trabalho pode ser desenvolvido separadamente antes de ser integrado à branch principal.
