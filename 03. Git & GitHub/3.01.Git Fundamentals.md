# 3.01. Git Fundamentals
Neste módulo, o foco será entender como o Git funciona e como ele é utilizado junto com GitHub no fluxo de trabalho.

## O que é Git?
Git é um sistema de controle de versão distribuído, utilizado para acompanhar as alterações realizadas em arquivos de um projeto.

Ele permite registrar diferentes versões do projeto, consultar o histórico de alterações e recuperar versões anteriores quando necessário.

O Git pode ser utilizado localmente, sem depender do GitHub. 

Já o GitHub é uma plataforma que utiliza Git e permite armazenar repositórios remotamente, além de facilitar a colaboração entre pessoas e equipes.

## Git vs GitHub
Apesar de estarem relacionados, Git e GitHub não são a mesma coisa.
- **Git** é o sistema de controle de versão.
- **GitHub** é uma plataforma utilizada para hospedar repositórios Git e colaborar em projetos.

## Criando um repositório com `git init`
Para começar a utilizar o Git em um projeto existente, é necessário inicializar um repositório dentro da pasta do projeto. Para isso, você pode utilizar, por exemplo, o terminal do computador, o terminal integrado do VS Code ou o Git Bash, uma ferramenta instalada juntamente com o Git.

O comando `git init` inicializa um novo repositório Git na pasta atual. A partir desse momento, o projeto passa a ter um repositório Git, permitindo que as alterações sejam acompanhadas e registradas por meio dos comandos do Git.

Depois de inicializar o repositório, você pode verificar seu estado utilizando o comando `git status`.

O comando `git status` ajuda a verificar quais arquivos foram modificados, quais alterações estão preparadas para commit e quais arquivos ainda não estão sendo acompanhados pelo Git.


## Repositório
Um repositório Git é o local onde o Git acompanha os arquivos e mantém o histórico de alterações do projeto.

Um projeto pode ter um repositório Git local no computador e depois esse repositório pode ser conectado a um repositório remoto no GitHub ou outra plataforma que esteja a usar.

## Os Três Estados
As alterações realizadas em um projeto passam por diferentes etapas antes de serem registradas em um commit:

```
Working Directory
       ↓
Staging Area
       ↓
Repository
```

### Working Directory
É a área onde os arquivos do projeto estão sendo modificados.

Quando um arquivo é criado ou alterado, a mudança inicialmente está no Working Directory.

### Staging Area
É a área utilizada para preparar as alterações que farão parte do próximo commit.

O comando `git add` adiciona as alterações selecionadas à Staging Area.

### Repository
É onde os commits são registrados e o histórico das alterações é mantido.

O comando `git commit` registra no repositório as alterações que foram previamente colocadas na Staging Area.

## Commits
Um commit registra um conjunto de alterações no histórico do repositório.

Cada commit representa um estado do projeto naquele momento e possui informações que permitem consultar seu histórico posteriormente.

Por isso, commits devem representar alterações que façam sentido e tenham uma descrição clara do que foi realizado.

## Principais comandos
| Comando      | Função                                           |
| ------------ | ------------------------------------------------ |
| `git init`   | Inicializa um novo repositório Git.              |
| `git add`    | Adiciona alterações à Staging Area.              |
| `git status` | Mostra o estado atual dos arquivos e alterações. |
| `git commit` | Registra as alterações preparadas no histórico.  |
| `git log`    | Exibe o histórico de commits.                    |
| `git diff`   | Mostra diferenças entre versões ou alterações.   |


## Fluxo básico
Um fluxo simples para registrar uma alteração pode ser:

```
git status
git add .
git status
git commit -m "Update test documentation"
```

O `git add` prepara as alterações para o próximo commit e pode ser usado com `.` para incluir todos os arquivos no commit ou apenas com nome do arquivo que quer incluir ao commit. O `git commit` registra essas alterações no histórico do repositório.

## 💡 Git no dia a dia de um QA
Durante um projeto, o QA pode precisar criar ou alterar scripts de automação, atualizar casos de teste, modificar arquivos de configuração ou revisar documentação.

Essas alterações podem ser versionadas com o Git, permitindo acompanhar o histórico das mudanças, identificar o que foi alterado e, quando necessário, recuperar versões anteriores dos arquivos.

O Git pode ser utilizado para versionar diferentes artefatos relacionados aos testes, como:

- casos de teste;
- scripts de automação;
- arquivos de configuração;
- documentação;
- dados de teste não sensíveis.

O controle de versão ajuda o QA a manter um histórico organizado do trabalho, acompanhar a evolução dos arquivos e colaborar com outros integrantes da equipe.

Em conjunto com plataformas como o GitHub, recursos como **branches, commits e Pull Requests**(*) também facilitam a revisão e integração das alterações realizadas pelo time.
