# 2.11. Checklists
Um **Checklist** é uma lista de itens que devem ser verificados durante a execução dos testes para garantir que aspectos importantes da funcionalidade sejam avaliados.

Diferentemente de um caso de teste, o checklist não descreve detalhadamente os passos de execução, servindo como um guia para orientar as validações.

Os checklists têm como objetivo organizar e padronizar a execução dos testes, ajudando a garantir que verificações importantes não sejam esquecidas.

Também podem ser reutilizados em testes recorrentes e em funcionalidades semelhantes.

## Exemplo:
### Funcionalidade:
Tela de Login

### Checklist:
- [ ] Validar login com credenciais válidas.
- [ ] Validar login com senha incorreta.
- [ ] Validar usuário inexistente.
- [ ] Validar campos obrigatórios.
- [ ] Validar mensagens de erro.
- [ ] Validar recuperação de senha.


## Checklist × Test Case
Um erro comum é achar o **Checklist** é uma versão "inferior" do **Test Case** quando na realidade, eles têm propósitos diferentes. Um checklist é mais leve, enquanto um caso de teste é mais detalhado. Dependendo do contexto, um checklist pode ser a melhor escolha.

| Checklist                                                | Test Case                                             |
| -------------------------------------------------------- | ----------------------------------------------------- |
| Lista o que deve ser verificado.                         | Descreve detalhadamente como executar o teste.        |
| Não possui passos detalhados.                            | Contém passos, dados de teste e resultados esperados. |
| Mais simples e rápido de criar.                          | Mais completo e detalhado.                            |
| Indicado para verificações rápidas e testes recorrentes. | Indicado para validações detalhadas e reprodutíveis.  |

## O papel do QA
O QA utiliza checklists para organizar a execução dos testes, garantir a cobertura das principais verificações e padronizar atividades que são realizadas com frequência.


## 💡 Boa prática
Checklists são especialmente úteis quando a funcionalidade já é conhecida ou quando o objetivo é realizar verificações rápidas. Para funcionalidades mais complexas ou críticas, normalmente são complementados por casos de teste detalhados.

Embora os dois conceitos estejam relacionados, eles não são exatamente a mesma coisa. O primeiro explica **uma técnica para projetar os testes**, enquanto este explica **um documento utilizado durante a execução dos testes**.
