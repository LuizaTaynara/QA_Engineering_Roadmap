# 2.04. Requirement Analysis
A **Análise de Requisitos** é o processo de revisar e compreender os requisitos de software para verificar se estão claros, completos, consistentes e testáveis antes do início do desenvolvimento.

Seu objetivo é identificar dúvidas, ambiguidades, informações ausentes e possíveis riscos que possam comprometer a implementação ou a validação da funcionalidade.

A análise de requisitos busca garantir que todos os envolvidos no projeto compartilhem o mesmo entendimento sobre o que deve ser desenvolvido.

Uma análise realizada nas fases iniciais do projeto reduz retrabalho, facilita o planejamento dos testes e contribui para a entrega de um software com maior qualidade.

## O que analisar?
Durante a análise de requisitos, é recomendável verificar aspectos como:
- Clareza das informações.
- Ambiguidades ou interpretações diferentes.
- Regras de negócio.
- Fluxos principais e alternativos.
- Tratamento de erros e exceções.
- Critérios de aceite.
- Dependências entre funcionalidades.
- Requisitos funcionais e não funcionais.
- Possíveis riscos para o projeto.

## Perguntas que o QA pode fazer
Durante a análise dos requisitos, é comum que o QA faça perguntas para esclarecer dúvidas e evitar interpretações incorretas.

Alguns exemplos:
- O comportamento esperado está claramente definido?
- Existem cenários alternativos ou exceções que não foram considerados?
- Os critérios de aceite cobrem todos os fluxos da funcionalidade?
- Há dependências com outros sistemas ou funcionalidades?
- Os requisitos são testáveis?
- Existe alguma regra de negócio que precise ser detalhada?

Essas perguntas ajudam a identificar lacunas antes do desenvolvimento e contribuem para uma especificação mais completa.

## O papel do QA
O QA participa da análise de requisitos desde as primeiras etapas do projeto, revisando a documentação e colaborando com a equipe para identificar inconsistências, esclarecer dúvidas e reduzir riscos.

Sempre que encontrar informações incompletas ou conflitantes, o QA deve buscar esclarecimentos com o responsável pelo requisito ou com a equipe envolvida, garantindo que todos tenham o mesmo entendimento antes do início do desenvolvimento.

## 💡 Boa prática
Sempre que possível, revise os requisitos antes de analisar a implementação da funcionalidade. Essa abordagem facilita a identificação de inconsistências e reduz a influência da solução implementada na interpretação dos requisitos.
