## 4.01. Test Execution
**Test Execution (Execução de Testes)** é a etapa em que os testes planejados são executados para verificar o comportamento do software e comparar os resultados obtidos com os resultados esperados.

Durante a execução, o QA registra os resultados dos testes e, quando identifica um comportamento diferente do esperado, analisa a situação para determinar se existe um defeito que precisa ser reportado. Dependendo da ferramenta ou do processo utilizado pela equipe, podem ser utilizados diferentes status, como:

- **Passed** — o resultado obtido corresponde ao esperado.
- **Failed** — o resultado obtido não corresponde ao esperado e a situação deve ser analisada.
- **Blocked** — o teste não pode ser executado devido a algum impedimento.

O registro dos resultados ajuda a acompanhar o andamento dos testes e identificar quais funcionalidades precisam de atenção.

De forma simplificada, a execução pode seguir este fluxo:

```
Test Case
    ↓
Executar o teste
    ↓
Obter o resultado
    ↓
Comparar com o resultado esperado
    ↓
Passou ou Falhou
```

### Exemplo prático
Imagine um caso de teste para o login:

```
Resultado esperado:
O usuário deve acessar a aplicação após informar credenciais válidas.

Resultado obtido:
O usuário acessou a aplicação corretamente.

Status:
Passed
```

E se o sistema não permitir o acesso mesmo utilizando credenciais válidas?

```text
Resultado esperado:
O usuário deve acessar a aplicação após informar credenciais válidas.

Resultado obtido:
O usuário não acessou a aplicação corretamente e uma mensagem de erro foi apresentada.

Status:
Failed
```

Nesse caso, o QA deve investigar o comportamento e se for confirmado um defeito, realizar o seu registro conforme o processo utilizado pela equipe.

## 💡 Papel do QA
Durante a execução dos testes, o QA deve seguir as condições definidas para cada teste, registrar os resultados obtidos e fornecer informações suficientes para que os problemas encontrados possam ser analisados e acompanhados.

A execução também pode gerar informações importantes para as próximas atividades de teste, especialmente quando são identificados novos comportamentos, riscos ou defeitos.
