# 📖 3.07. GitHub Actions
O **GitHub Actions** é uma plataforma de automação integrada ao GitHub que permite criar workflows para executar tarefas automaticamente dentro de um repositório.

Esses workflows podem ser utilizados para automatizar atividades como build, testes e outras tarefas do processo de desenvolvimento. 

> Neste módulo, o foco será compreender os conceitos básicos e utilizar o GitHub Actions para automatizar tarefas relacionadas aos testes.


## O que é um Workflow?
Um **workflow** é um processo automatizado definido por um arquivo YAML(*) dentro do repositório.

Os arquivos de workflow devem ser armazenados no diretório:

```
.github/workflows/
```

Um repositório pode possuir vários workflows, cada um responsável por diferentes tarefas.

Um workflow pode, por exemplo, ser configurado para executar testes sempre que uma alteração for enviada ao repositório.

> ###### (*) Um arquivo YAML é um arquivo de texto usado principalmente para armazenar configurações e estruturar dados de forma organizada e legível. A extensão mais comum é .yml ou .yaml.

## Principais conceitos
Um workflow possui alguns elementos principais: Event, Job, Step, Action e Runner

### Event
É o evento que inicia a execução do workflow.

Alguns exemplos são:

- `push`;
- `pull_request`;
- execução manual;
- execução em horários definidos.

Os eventos são configurados utilizando a chave `on`.

### Job
Um **job** é um conjunto de etapas que será executado em um runner.

Um workflow pode possuir um ou vários jobs. 

### Step
Um **step** é uma etapa individual dentro de um job.

Um step pode executar um comando ou utilizar uma Action. 

### Action
Uma **Action** é uma unidade reutilizável de automação que pode ser utilizada dentro de um workflow.

Existem Actions disponibilizadas pelo GitHub, pela comunidade e também é possível criar Actions próprias. 

### Runner
O **runner** é a máquina responsável por executar os jobs do workflow.

O GitHub disponibiliza runners hospedados por ele, e também existem opções de runners próprios. 

## Criando um Workflow
Um workflow é criado em um arquivo `.yml` ou `.yaml` dentro do diretório `.github/workflows/`.

Exemplo simples:

```
name: Run Tests

on:
  push:

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v6

      - name: Run tests
        run: echo "Running tests..."
```

Nesse exemplo:

- `name` define o nome do workflow;
- `on` define o evento que inicia o workflow;
- `jobs` define os jobs;
- `runs-on` define o runner utilizado;
- `steps` define as etapas;
- `uses` utiliza uma Action;
- `run` executa um comando.

A documentação oficial utiliza essa mesma estrutura básica para apresentar a criação de um primeiro workflow.

## 💡 GitHub Actions para QA
O **GitHub Actions** pode ser utilizado para automatizar a execução de testes. Um workflow pode ser configurado para executar testes automaticamente quando uma alteração é enviada ao repositório ou quando um Pull Request é criado.

Exemplo:

Em um projeto de automação com **Python**, podemos criar um workflow para executar os testes automaticamente após um `push`.

Esse workflow é definido em um arquivo **YAML** e pode conter as etapas necessárias para preparar o ambiente e executar os testes:

```yaml
name: Automated Tests

on:
  push:

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v6

      - name: Install dependencies
        run: pip install -r requirements.txt

      - name: Run tests
        run: pytest
```

Nesse exemplo, o GitHub Actions:

1. inicia o workflow após um `push`;
2. prepara o ambiente de execução;
3. instala as dependências do projeto;
4. executa os testes com `pytest`;
5. disponibiliza o resultado da execução.

Dessa forma, é possível verificar automaticamente se os testes continuam funcionando após alterações no projeto.
