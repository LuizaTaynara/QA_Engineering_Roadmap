# 1.13. Test Pyramid
A **Pirâmide de Testes** é um modelo que representa como diferentes níveis de testes podem ser distribuídos em um projeto de software. Seu objetivo é orientar a criação de uma estratégia de testes equilibrada, priorizando testes mais rápidos, estáveis e de menor custo de manutenção.

O conceito foi popularizado por **Mike Cohn** no livro *Succeeding with Agile*.

## Estrutura da Pirâmide
De forma simplificada, pois a forma da pirâmide pode variar conforme a estratégia e o contexto do projeto, a Pirâmide de Testes é composta por três níveis: Base, meio e topo.

### Base — Unit Tests
Os **Testes de Unidade** formam a base da pirâmide por serem rápidos, de baixo custo e cobrirem pequenas partes do código de forma isolada. Por isso, normalmente representam a maior quantidade de testes em um projeto.

As ferramentas populares para fazer testes de unidade são:
- Jest e Vitest (JavaScript/TypeScript)
- Jasmine
- JUnit (Java)
- PyTest (Python)


### Meio — Integration Tests
Os **Testes de Integração** verificam se diferentes componentes do sistema funcionam corretamente em conjunto, como a comunicação entre serviços, APIs e banco de dados.

Embora sejam mais lentos que os testes de unidade, continuam sendo importantes para validar a integração entre as partes do sistema.

As ferramentas utilizadas para testes de unidade também podem ser utilizadas em testes de integração, dependendo da tecnologia e do contexto do projeto. Em alguns casos específicos, existem frameworks que tornam sua vida bem mais fácil, como:
- Karma para o Angular
- React Testing Library no React


### Topo — End-to-End Tests
Os **Testes de Ponta a Ponta (E2E)** validam o funcionamento completo da aplicação, simulando a interação do usuário com o sistema.

Por envolverem diversos componentes, costumam ser mais lentos, mais complexos e demandam maior manutenção. Por isso, geralmente são executados em menor quantidade.

As ferramentas populares de testes de ponta a ponta são:
- Cypress
- Playwright
- Puppeteer

## O papel do QA
A Pirâmide de Testes auxilia o QA na definição de uma estratégia de testes mais eficiente. Embora o desenvolvimento dos testes de unidade seja geralmente responsabilidade dos desenvolvedores, o QA pode contribuir para o planejamento, implementação e manutenção de testes de integração e End-to-End, dependendo da organização e da divisão de responsabilidades da equipe.
