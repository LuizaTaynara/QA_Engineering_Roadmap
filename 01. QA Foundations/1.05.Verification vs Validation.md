# 1.05. Verification vs. Validation
Embora os termos **Verification** e **Validation** sejam frequentemente utilizados em conjunto, eles representam atividades diferentes no processo de desenvolvimento de software.

- **Verification (Verificação)** busca responder à pergunta: **"Estamos desenvolvendo o produto corretamente?"**
- **Validation (Validação)** busca responder à pergunta: **"Estamos desenvolvendo o produto certo?"**

Ambas são importantes para garantir que o software atenda aos requisitos especificados e às necessidades dos usuários.

## Verification (Verificação)
A **Verification** consiste em avaliar verifica se o produto está sendo desenvolvido de acordo com os requisitos e especificações.

Seu objetivo é identificar problemas antes da implementação ou da execução do software.

Algumas atividades de verificação incluem:
- Revisão de requisitos;
- Revisão de casos de teste;
- Revisão de documentação;
- Inspeções;
- Revisão de código (*Code Review*).

## Validation (Validação)
A **Validation** consiste em avaliar se o software implementado atende às necessidades do usuário e aos objetivos para os quais foi desenvolvido.

Essa avaliação normalmente ocorre por meio da execução de testes.

Algumas atividades de validação incluem:
- Testes funcionais;
- Testes de integração;
- Testes de sistema;
- Testes de aceitação do usuário (UAT).


## Comparativo
| Aspecto                 | Verification                                  | Validation                                          |
| ----------------------- | --------------------------------------------- | --------------------------------------------------- |
| **Pergunta principal**  | Estamos desenvolvendo o produto corretamente? | Estamos desenvolvendo o produto certo?              |
| **Foco**                | Conformidade com requisitos e especificações  | Atendimento às necessidades do usuário e do negócio |
| **Objeto de avaliação** | Artefatos do desenvolvimento                  | Software em execução                                |
| **Exemplos**            | Revisões, inspeções e análise de documentos   | Execução de testes e validação da solução           |


## Exemplo prático
Considere o desenvolvimento de uma funcionalidade de recuperação de senha.

**Verification:** Durante a revisão da User Story, o QA identifica que os critérios de aceite não informam o tempo de expiração do link de recuperação de senha. A inconsistência é corrigida antes do desenvolvimento.

**Validation:** Após a implementação da funcionalidade, o QA executa testes para verificar se o e-mail é enviado corretamente, se o link permite redefinir a senha e se expira conforme especificado.

Verification e Validation são atividades complementares no processo de desenvolvimento de software.
