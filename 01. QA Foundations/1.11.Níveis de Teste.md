# 1.11 Test Levels
Os **Níveis de Teste** representam as diferentes etapas em que os testes são planejados e executados durante o ciclo de desenvolvimento de software. Cada nível possui um objetivo específico, um escopo definido e contribui para verificar e validar diferentes partes do sistema.

Os quatro níveis de teste mais utilizados são: **Unit Testing**, **Integration Testing**, **System Testing** e **Acceptance Testing**.

## 1. Unit Testing
O **Teste de Unidade** verifica o funcionamento da menor parte testável do software, como uma função, método ou classe. Seu objetivo é garantir que cada unidade funcione corretamente de forma isolada.

## 2. Integration Testing
O **Teste de Integração** verifica se diferentes componentes ou módulos do sistema funcionam corretamente quando integrados. 

Seu objetivo é identificar falhas na comunicação e na troca de dados entre as partes da aplicação.

## 3. System Testing
O **Teste de Sistema** avalia o sistema completo e integrado para verificar se ele atende aos requisitos funcionais e não funcionais definidos.

Nessa etapa, o software é testado como um todo, simulando seu funcionamento em um ambiente semelhante ao de produção.

## 4. Acceptance Testing
O **Teste de Aceitação** verifica se o sistema atende às necessidades do negócio e aos critérios de aceite definidos para o produto.

Seu objetivo é confirmar que o software está pronto para ser entregue aos usuários ou ao cliente.

Esse nível pode incluir diferentes abordagens, como **User Acceptance Testing (UAT)**, **Operational Acceptance Testing (OAT)**, **Alpha Testing** e **Beta Testing**, dependendo do contexto do projeto.

## O papel do QA
O QA pode atuar em todos os níveis de teste, embora sua participação varie conforme a organização e o projeto. Em geral, colabora no planejamento, elaboração e execução dos testes de integração, sistema e aceitação, além de apoiar a definição dos critérios de qualidade e garantir que os requisitos sejam devidamente validados antes da entrega do software.

## Observação
É comum encontrar materiais afirmando que:

- Unit Test = Desenvolvedor
- Integration Test = QA
- System Test = QA
- Acceptance Test = Cliente

Entretanto, segundo o **ISTQB**, os níveis de teste **não são definidos por quem executa os testes**, mas pelo **objetivo** do teste. Dependendo da organização, desenvolvedores, QAs, analistas de teste e até usuários podem participar de diferentes níveis.
