>Uma observação rápida: **não existe uma lista única e definitiva de tipos de teste**. O próprio ISTQB afirma que os testes podem ser classificados por diferentes perspectivas. Para um QA Júnior, o mais útil é conhecer os tipos mais utilizados no mercado.

# 1.12. Test Types
Os **Tipos de Teste** classificam os testes de acordo com o objetivo da avaliação realizada no software. Enquanto os **níveis de teste** indicam ***"onde"*** o software será testado, os **tipos de teste** definem ***"o que"*** será avaliado.

Os testes podem verificar funcionalidades, desempenho, segurança, usabilidade, compatibilidade e outros atributos de qualidade do sistema.

## 1. Functional Testing
O **Teste Funcional** verifica se o software funciona conforme os requisitos especificados, validando se cada funcionalidade produz o resultado esperado.

## 2. Non-Functional Testing
O **Teste Não Funcional** avalia características de qualidade que não estão relacionadas diretamente às funcionalidades do sistema, como desempenho, segurança, usabilidade e confiabilidade.

## 3. Smoke Testing
O **Teste de Fumaça** consiste em um conjunto reduzido de testes executados para garantir que as funcionalidades essenciais do sistema estão funcionando corretamente antes da realização de testes mais detalhados. Isso significa que você não precisa testar cada elemento a fundo. 

## 4. Regression Testing
O **Teste de Regressão** verifica se alterações realizadas no software, como correções de defeitos, novas funcionalidades ou mudanças no código, não afetaram elementos que já estavam funcionando corretamente. Seu objetivo é garantir que o sistema continue se comportando conforme o esperado após as modificações. 

## 5. Retesting (Confirmation Testing)
O **Reteste**, também chamado de **Teste de Confirmação**, consiste em executar novamente um teste para confirmar que um defeito corrigido realmente foi resolvido.

Diferentemente do teste de regressão, o reteste verifica apenas a funcionalidade que apresentou o defeito.

## 6. Exploratory Testing
O **Teste Exploratório** combina aprendizado, planejamento e execução de testes de forma simultânea, permitindo que o testador explore o sistema sem depender exclusivamente de casos de teste previamente definidos.

Essa abordagem é útil para identificar comportamentos inesperados e defeitos que poderiam não ser encontrados em testes roteirizados.

## O papel do QA
O QA seleciona os tipos de teste mais adequados de acordo com os objetivos do projeto, os riscos identificados e as características do software. Em muitos projetos, diferentes tipos de teste são utilizados em conjunto para aumentar a cobertura e contribuir para a qualidade do produto.
